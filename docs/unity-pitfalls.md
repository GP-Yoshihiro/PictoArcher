# Unity の落とし穴（初めての人向け）

Unity を初めて使う人と、その人の Claude が勘違いしやすい所をまとめた。各項目は「何が起きるか／なぜか／ここではどうするか」の3行で書く。
規則の正本は `docs/superpowers/specs/2026-11-14-coding-rules-design.md`、書き方のお手本はスキル `.claude/skills/pictoarcher-coding-rules/SKILL.md`。

## 1. ScriptableObject を実行中に書き換えると、値がアセットに残る
- **何が起きるか**：再生中に `PlayerStats` などの値をコードで変えると、再生を止めても元に戻らない。気づかないままコミットされる。
- **なぜか**：エディタでは ScriptableObject はアセットそのものを読み込んでいるので、書き換えはファイルへの書き換えになる。
- **ここではどうするか**：ScriptableObject は読み取り専用（public の setter を作らない）。実行中に変わる値は、データから作った普通の C# のオブジェクトに持たせる。

## 2. Destroy したオブジェクトに `?.` や `??` が効かない
- **何が起きるか**：`enemy?.TakeDamage()` が、Destroy 済みの敵でも呼ばれて `MissingReferenceException` になる。
- **なぜか**：Unity のオブジェクトは `== null` を独自に上書きしているが、`?.` と `??` はその上書きを通らない。
- **ここではどうするか**：Unity のオブジェクトは `if (x == null)` で確かめる。`CollisionRelay2D.Touching` の中身も同じ。

## 3. Destroy はすぐには消えない
- **何が起きるか**：`Destroy(obj)` の直後でも、そのフレームの間は `obj` が見つかったり当たり判定に出たりする。
- **なぜか**：Destroy はフレームの終わりにまとめて行われる。
- **ここではどうするか**：消すと決めたものは、自分の一覧（`EnemyRegistry` や System の一覧）から先に外す。一覧を回しながら消すときは `TickList` を使う。

## 4. `[SerializeField]` の名前を変えると値が消える
- **何が起きるか**：フィールドの名前を変えると、インスペクターで入れた値やアセットの値が既定値に戻る。
- **なぜか**：シーン・プレハブ・アセットは、値をフィールドの名前で保存している。
- **ここではどうするか**：名前を変えるときは `[FormerlySerializedAs("古い名前")]` を付ける（`PlayerStats` が例）。

## 5. `.meta` は必ずコミットする
- **何が起きるか**：`.meta` を入れ忘れると、ほかの人の環境でプレハブやシーンのつながりが切れる（Missing になる）。
- **なぜか**：Unity はファイルを `.meta` の中の GUID で覚えている。`.meta` がないと別の GUID が作られる。
- **ここではどうするか**：ファイルを足したら `.meta` も一緒にコミットする。移すときは `git mv` で `.meta` も一緒に移す。

## 6. シーンとプレハブは2人で同時に直すと衝突する
- **何が起きるか**：同じシーンやプレハブを2人が直すと、マージで壊れたり片方の変更が消えたりする。
- **なぜか**：中身は YAML だが、人が読んで直せる形ではなく、自動のマージがうまくいかないことが多い。
- **ここではどうするか**：`Root.unity`・`Home.unity`・`Battle.unity`・`Result.unity`・`Pause.unity` を直すのは C さんだけ。ほかの人はプレハブと `Scenes/Sandbox/Sandbox_<担当>.unity` で作業する。同じプレハブを触る PR が開いていたら作業を始めない。

## 7. 物理で動かすものは `Rigidbody2D` を使い、`FixedTick` で動かす
- **何が起きるか**：`Rigidbody2D` を持つものを `transform.position` で動かすと、壁をすり抜けたりカクついたりする。
- **なぜか**：物理は `FixedUpdate` の間隔で計算されるので、それとずれた所で位置を直接変えると計算と食い違う。
- **ここではどうするか**：物理で動かすものは `Rigidbody2D.MovePosition` や `linearVelocity` を使い、シーンの `FixedTick` から呼ばれる所で動かす。

## 8. 入力は Tick で読む
- **何が起きるか**：`FixedTick` で「押した瞬間」を読むと、押したのに反応しないことがある。
- **なぜか**：`FixedUpdate` は1フレームに0回のことも2回のこともあり、「このフレームで押した」を取りこぼす。
- **ここではどうするか**：入力はシーンの `Tick` の中で `ReadValue` / `WasPressedThisFrame` で読み、結果を持っておいて `FixedTick` で使う。`performed +=` などのコールバックは使わない。

## 9. `GetComponent` は毎フレーム呼ばない
- **何が起きるか**：毎フレーム `GetComponent` や `transform` を呼ぶと、敵が増えたときに重くなる。
- **なぜか**：`GetComponent` は毎回探しに行く。
- **ここではどうするか**：インスペクターでつなぐか、`Init` で1回だけ取ってフィールドに持っておく。

## 10. たくさん作って消すものはプールで使い回す
- **何が起きるか**：弾や敵を毎回 `Instantiate` と `Destroy` すると、ガベージコレクションでときどき止まる。
- **なぜか**：作るたびにメモリを取り、消すたびにゴミが出る。
- **ここではどうするか**：弾のように数の多いものは、使い終わったら非表示にして一覧に戻し、次に使い回す（プール）。プールは持ち主の System が持つ。

## 11. static の値が再生をまたいで残る
- **何が起きるか**：再生を止めて、もう一度再生しても、static の値が前の再生のまま残っている。
- **なぜか**：このプロジェクトは再生を速くするため「ドメインのリロード」を切っている。リロードがないと static は初期化されない。
- **ここではどうするか**：static の書き換えられる値を持たない（ガードテストが止める）。全体で1つのものは `Main` が作る `GameContext` に持たせる。

## 12. Unity が呼ぶ順番は、オブジェクトどうしでは決まっていない
- **何が起きるか**：A の `Update` が B の `Update` より先に呼ばれる日と、後に呼ばれる日がある。順番に頼ったコードがたまに壊れる。
- **なぜか**：Unity は同じ種類のメソッドを呼ぶ順番を保証していない。
- **ここではどうするか**：標準ライフサイクルは `Main` だけが使い、`Main` → シーン → System の順にソースに書いた順番で呼ぶ。

## 13. タグやレイヤーを文字列や数字で書かない
- **何が起きるか**：`"Enemy"` の打ち間違いや、レイヤーの番号の変更で、当たり判定が黙って効かなくなる。
- **なぜか**：文字列や数字はコンパイラーが確かめてくれない。
- **ここではどうするか**：`Layers.Enemy`、`Layers.EnemyMask` などの定数を使う（番号は `LayersTests` が確かめる）。タグは使わない。

## 14. プレハブのインスタンスで変えた値は、プレハブ本体には入らない
- **何が起きるか**：シーンに置いたプレハブの値を変えても、ほかのシーンや新しく作ったものには反映されない。
- **なぜか**：インスタンスでの変更は「上書き」としてシーンの側に保存される（インスペクターで太字になる）。
- **ここではどうするか**：みんなに効かせたい値はプレハブを開いて直す。数値は ScriptableObject に置き、プレハブやシーンに直接書かない。

## 15. TextMeshPro を置くと「New Text」が入っている
- **何が起きるか**：UI に TextMeshPro を足すと、最初から英字の「New Text」が入っていて画面に出る。
- **なぜか**：Unity が見本の文字を入れて作る。
- **ここではどうするか**：文字ゼロのルール（`CLAUDE.md`）のとおり、画面に出すのは数字と記号だけ。足したらすぐに中身を消すか、数字だけにする。ボタンに文字の子を付けない。

## 16. シーンを加算で読み込むと、カメラや EventSystem が2つになる
- **何が起きるか**：Root の上に Home や Battle を重ねたとき、そのシーンにもカメラ・AudioListener・EventSystem があると、警告が出たり、ボタンが二重に反応したり、画面が乱れたりする。
- **なぜか**：加算（Additive）で読み込むと、前のシーンのものは消えずに残り、両方が動く。
- **ここではどうするか**：カメラ・AudioListener・EventSystem・`Main` は `Root.unity` にだけ置く（`SceneSetupTests` が確かめる）。新しいシーンや Sandbox のシーンを作ったら、Unity が最初に入れる Main Camera を消す。シーンを読み込む・外すのは `SceneTransform` だけで、自分で `SceneManager` を呼ばない。
