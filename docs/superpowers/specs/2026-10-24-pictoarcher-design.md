## 1. 目的と理由

アーチャー伝説（Archero）型のローグライトアクションを、**文字を一切使わずに**作る。【決定】

前提は次の3つ。【決定】

1. 文字ゼロ（数字・記号・ピクトグラムは使ってよい）
2. 初見で分かる（説明なしで遊び始められる）
3. 動かして面白い（触った瞬間に気持ちいい）

コンセプトは **「撃ちながら避け続ける。強くなるほど矢が目に見えて増える」**。【提案】
強化の結果が必ず画面上の見た目の変化として現れるようにすることで、文字の説明がなくてもスキルの意味が伝わる。

## 2. ゴール／やらないこと／失敗とみなすこと

**ゴール**
- 1章（10部屋）を最初から最後まで、説明なしで遊び切れる
- 初見の人が下の「合格ライン」（§14）を満たす

**やらないこと（8週間の範囲外）**
- スマホ対応、オンライン要素、課金や広告、装備、図鑑、デイリー要素
- 章2と🏹強化は「余裕があれば」（§13）

**失敗とみなすこと（動いていても失敗）**
- 画面のどこかに文字が1つでも出る（ロゴ、素材、エラー表示、ウィンドウタイトルの扱いは §5）
- 初見の人が「何をすればいいの？」と口にする
- スキルを選んでも何が変わったか分からない

## 4. 操作とコア体験

| 操作 | 内容 | 出所 |
|---|---|---|
| 移動 | WASD／矢印キー、またはマウス左ボタンを押したままドラッグ（押した位置が仮想スティックの中心） | 【提案】 |
| 射撃 | **常に自動射撃。移動中も撃てる**。一番近い敵を自動で狙う | 【決定】移動中も可／【提案】自動照準 |
| カード選択 | クリック、または 1 2 3 キー | 【提案】 |
| 一時停止 | Esc で ⏸ | 【提案】 |

- 移動中の連射速度は調整用の値として用意する（初期値は止まっているときと同じ 100%）。手触りを見て下げるかどうか決める。【提案】
- 敵がいないときは撃たない。【提案】
- 被弾したら短い無敵時間（点滅）。【提案】

## 5. 文字ゼロのルール（全員必読）

| 項目 | ルール |
|---|---|
| 禁止 | アルファベット・ひらがな・カタカナ・漢字すべて。`LV` `HP` `BOSS` `x2` `s`（秒）などの略語・単位も禁止 |
| 代わりの表記 | レベル `★5`／倍率 `×2`／時間 `⏱ 30`／割合 `+20%`／進行 `7/10` |
| 色の意味 | 赤＝危険・攻撃／緑＝回復／黄＝コイン・経験値／青＝防御・氷／紫＝レア |
| 予兆 | 敵の攻撃は必ず先に赤い線・赤い円で予告する |
| 操作の案内 | 手・矢印キー・マウスの絵のアニメで見せる。キーの絵に英字（W A S D、Esc など）を描かない |
| 絵文字 | フォントで出さない。すべてスプライト画像で用意する |
| フォント | TextMeshPro のフォントアセットには **数字と記号だけ** を登録する（英字はそもそも表示できない状態にする） |
| ボタン | ▶ 開始／⏸ 一時停止／↻ やり直し／🏠 ホーム／⚙ 設定／🔒 ロック中／🔊 音量 |
| 素材 | 取り込む前に文字が入っていないか確認する（UIパックの「PLAY」、看板、ロゴなど） |
| ウィンドウ・起動画面 | ウィンドウタイトルとアプリ名は OS が表示するもので画面内ではないため対象外とする。Unity のスプラッシュ画面はロゴを含むので、出せない場合は扱いをチームで判断する【提案】 |

## 6. ゲーム進行フロー

```
[起動]
  ├ 初回 → タイトルを出さずにチュートリアル部屋へ
  └ 2回目以降 → ホーム
[ホーム] ステージ地図（① ② …、未解放は 🔒）／▶／⚙／（🏹強化：余裕があれば）
   ↓ ▶
[ラン] 1章 = 10部屋
   部屋1〜4  通常戦闘
   部屋5     中ボス（入る前に ⚠ が点滅）
   部屋6     天使部屋（♥回復 か スキル1つ を選ぶ）
   部屋7〜9  通常戦闘（敵が強くなる）
   部屋10    ボス（画面上部に 💀 付きのHPバー）
   ↓
[クリア] ★1〜3 ＋ 獲得コイン → ▶ 次の章 ／ 🏠
[死亡]   💀 → 到達部屋 `7/10` と取得スキルのアイコン → ↻ ／ 🏠
```

- 死亡するとそのランは終わり、スキルはリセット。【提案】
- ★の条件：★1 クリア／★2 クリア時の残りHPが半分以上／★3 さらに目標タイム以内。目標タイムは調整値。【提案】
- 保存するもの：解放済みの章、章ごとの最高★、コイン。保存方法は JSON ファイル。【提案】

### 1部屋の流れ
1. 入室 → 敵が出る位置に赤い `!` 円 → 敵が出現
2. 戦闘
3. 全滅 → 経験値とコインが自分に吸い寄せられる
4. 扉が開いて光る ➜ が出る → 扉に入ると次の部屋へ

### レベルアップ
経験値バーが満タン → 時間停止 → カード3枚 → 1枚選ぶと再開。部屋の途中でも発生する。【提案】

### 一時停止メニュー
▶ 再開／↻ やり直し／🏠 ホーム／🔊 音量。【提案】

## 7. チュートリアル（部屋0）【提案】

1. 敵1体だけの部屋。矢印キーとマウスの絵がアニメで動きを見せる → プレイヤーが動く
2. 近づくと自動で矢が飛ぶ → 撃つのは自動だと分かる
3. 1体目を倒すと必ずレベルアップ → カード選択を一度体験させる
4. 2体目は弾を撃つ敵。赤い予兆線を見せて、避けることを覚えさせる
5. 扉の ➜ が光る → 部屋1へ

案内の絵はプレイヤーが一度その操作をしたら消える。2回目以降の起動では出さない。

## 8. 敵とボス

### 通常の敵（5種）【提案】
| 敵 | 動き | 予兆 |
|---|---|---|
| スライム | プレイヤーを追ってくる、体当たり | なし（遅い） |
| 弓兵 | 止まって狙い、まっすぐ撃つ | 赤い線 |
| コウモリ | 速く不規則に飛ぶ | なし |
| 砲台植物 | 動かず、円形に弾をばらまく | 光ってから撃つ |
| 爆弾魔 | 突進して自爆 | 赤い円が広がる |

### 中ボス（部屋5）【提案】
巨大スライム。HPが減ると分裂する。

### ボス（部屋10）【提案】
3パターン：突進（赤い線）／弾幕（光ってから）／雑魚を呼ぶ（赤い `!` 円）。HPが半分を切ると間隔が短くなる。

数値（HP・攻撃力・速度・出現数）はすべて ScriptableObject の調整値として扱い、プレイテストで決める。

## 9. スキル（12種）【提案】

カードには **大きいアイコン＋数字＋約1秒の実演アニメ** を入れる。

| アイコン | 効果 | 画面での見え方 | 重ね取り |
|---|---|---|---|
| ⇉ | 前方の矢 +1 | 矢が並んで飛ぶ | 最大3 |
| ↖↗ | 斜めの矢 | V字に飛ぶ | 最大2 |
| ⇄ | 後ろにも撃つ | 背中側にも矢 | 1回 |
| ⤳ | 貫通 | 敵をすり抜ける | 1回 |
| ⟲ | 壁で跳ね返る | 壁で反射 | 最大2 |
| 🔥 | 炎 | 燃えて継続ダメージの数字 | 最大3 |
| ❄ | 氷 | 青くなり遅くなる | 最大3 |
| ⚡ | 連射 +% | 撃つ間隔が短くなる | 最大5 |
| 💥 | クリティカル | 大きい黄色の数字 | 最大5 |
| ⚔↑ | 攻撃力 +% | 矢が大きく光る | 最大5 |
| ♥↑ | 最大HPアップ＋回復 | HPバーが伸びる | 最大5 |
| ◎ | 周りを回る玉 | 自分の周囲を玉が回る | 最大3 |

- 重ね取りの段階はカードに `★★` のように表示する。
- 上限に達したスキルはカード候補から外す。
- カード3枚は重複なしでランダム。重み付けは調整値。

## 10. 画面表示（HUD）【提案】

| 場所 | 表示 |
|---|---|
| プレイヤーの頭上 | HPバー＋数字 |
| 画面上部 | 進行ドット `●●●○○…💀`、ボス戦ではボスのHPバー |
| 画面上部 | 経験値バー＋`★n`、コイン数 |
| 画面左右の余白 | 取得したスキルのアイコン一覧 |
| 右上 | ⏸ |
| 戦闘中 | ダメージ数字のポップアップ、ヒットストップ、画面の揺れ |

部屋は横長（16:9）の見下ろし視点で、1部屋＝1画面に収める（スクロールしない）。原作の縦長レイアウトは使わない。【提案】

開発ビルドやデバッグ表示でも画面に文字を出さない（ログはコンソールのみ）。【提案】

## 11. アートと音

- スキルアイコン：1週目にプログラマーが仮アイコン（単純な図形と記号）を作る。描く人が決まれば同じサイズ・同じ色ルールで差し替える。**差し替え期限は5週目**。過ぎたら仮アイコンで仕上げる。【提案】
- キャラ・敵・背景・効果音：フリー素材。なるべく1つのシリーズでまとめる（候補：Kenney、CC0）。【提案】
- ライセンス：ゲーム内にクレジット画面を作ると文字が出るため、**CC0 の素材を優先**する。表記が必要な素材を使う場合は、表記を README や配布ページなどゲームの外に書く。【提案】
- 素材一覧表 `docs/assets-list.md` を作り、入手先・ライセンス・使用箇所を記録する（担当：Cさん）。【提案】

## 12. 技術方針【提案】

| 項目 | 方針 |
|---|---|
| テンプレート | Unity 6 の 2D（URP 2D Renderer）テンプレートで作成済み |
| 入力 | Input System。キーボードとマウスのドラッグを同じ「移動ベクトル」に変換する |
| データ | スキル・敵・部屋の構成は ScriptableObject。新しいスキルや敵はデータを足すだけで増やせるようにする |
| 文字 | TextMeshPro、数字と記号だけのフォントアセット |
| シーン | Boot／Home／Run の3つ。部屋は Run シーン内でプレハブを切り替える |
| 共同作業 | シーンを同時に編集しない。担当ごとにプレハブを分け、シーン編集は1人に決める。Unity の YAML マージ（UnityYAMLMerge）を各自設定する |
| ビルド | Windows と Mac のスタンドアロン |
| テスト | 純粋なロジック（ダメージ計算、スキルの重ね取り、カードの抽選、進行）は Unity Test Framework の EditMode テストを書く |

## 13. 分担・スケジュール・削る順【提案】

### 分担
- **Aさん：プレイヤー**（操作、射撃、スキルの仕組みと12種の効果）
- **Bさん：敵**（敵AI 5種、中ボス、ボス、予兆表示、部屋ごとの敵の出方）
- **Cさん：進行とUI**（ホーム、カード選択、HUD、結果画面、チュートリアル、音、保存、素材一覧、アイコンのルール管理）

### スケジュール
| 週 | ゴール |
|---|---|
| 1 | 移動・自動射撃・敵1体が動く。スキル・敵のデータ形式を全員で決める。仮アイコン |
| 2 | 1部屋が最初から最後まで遊べる（入室 → 戦闘 → 扉 → 次の部屋） |
| 3 | レベルアップとカード3枚、スキル6種、敵3種。**ここから毎週、初見の人でテスト** |
| 4 | 全機能が入る：10部屋、中ボス、天使部屋、ボス、結果画面、保存 |
| 5–6 | 中身を揃える：スキル12種、敵5種、チュートリアル、難易度調整。スキルイラスト差し替え期限（5週目） |
| 7 | 手触りの仕上げ：ヒットストップ、揺れ、効果音、アイコン統一 |
| 8 | 新機能禁止。バグ修正と最終テストのみ |

### 遅れたときに削る順
章2 → 🏹強化 → ボスの3つ目のパターン → ◎ → コウモリ

予兆表示、チュートリアル、カードの実演アニメは「初見で分かる」の柱なので最後まで削らない。

削ったときの扱い【提案】
- 🏹強化を削る → コインは表示と保存だけ
- 章2を削る → 地図の②は常に 🔒

### テストのための準備【提案】
- 保存データを消して初回状態に戻すデバッグ用の操作（キーの組み合わせ）を用意する
- 操作案内の絵（§7）は、3週目のテストに間に合うよう最小版を先に入れる

## 14. 合格ライン（毎週のプレイテスト）【提案】

説明を一切せずに初見の人に渡して、

1. 30秒以内に自分から動いて敵を倒せるか
2. 3部屋目まで誰の助けもなく進めるか
3. スキルカードを選んだあと、その効果を自分で言えるか

テスト中は観察する人も口を出さない。止まった場所と、その人が口にした言葉を記録する。

## 15. 作る人に任せること

- 数値のバランス（HP、攻撃力、経験値の必要量、敵の出現数、目標タイム）
- 部屋のレイアウト（障害物の配置）
- エフェクトや効果音の細かい選び方
- コードの構成（§12 の方針の範囲内で）
