## 1. ひとことで

**乗っ取られた宇宙ステーションの一区画で、偵察兵が暴走した機械の波を50回しのぎ切る。**

- 光線銃なので、弾や跳ね返り（⟲）、貫通（⤳）が自然に見える。
- 機械の敵は、硬い部品の組み合わせで作れるので、動きの一部をプログラムで出せる（回転、上下の揺れ、点滅）。そのぶん絵のコマが少なくて済む。

## 2. フィールド

- 宇宙ステーションの格納庫（1画面、480×270 の中に壁まで収める）。中にいくつかコンテナと柱を置き、弾よけにも障害にもなる。
- 10ウェーブごとに照明を変える：1〜10 通常の白い照明／11〜20 薄暗い照明／21〜30 暗い紺色の照明／31〜40 照明がゆっくり明滅する／41〜50 外の惑星の淡い光（色合いは彩度を抑え、色の意味の5色に見えないようにする。警報灯のような赤い照明は使わない）
- 色合いの変化はプログラマーが照明と色調で出す。背景の絵は描き直さない。全体の色合いと明るさを変えるだけで、部分的な明かり（自分のまわりだけ明るい、など）は出さない。

## 3. キャラクターと敵

| 役割 | 姿 | ひと目で分かる理由 |
|---|---|---|
| プレイヤー | ヘルメットをかぶった偵察兵。光線銃を持つ | 銃を構える姿で「撃つ人」と分かる |
| 追う敵 | クモ型の小さな機械 | わさわさ近づく＝体当たり |
| 撃つ敵 | 一つ目の警備ロボ | 銃口を向ける＝撃ってくる |
| 固定砲台 | 床に据えた砲塔 | 動かない、光ったら撃つ |
| 自爆する敵 | コアが点滅する自爆ロボ | 点滅が速くなる＝爆発する |
| 中ボス（分裂） | 金属の粒が集まった塊 | 大きな塊が小さな塊に割れる |
| ボスA | 大型の二足メカ | 突進、胸のハッチが開いてクモ型を出す。20 からは足踏みで周りに範囲攻撃 |
| 最後のボス | ステーションの中枢機械（巨大な一つ目） | 突進、弾幕、雑魚を呼ぶ。HPが半分を切ると目の光と色が変わる（光り方はプログラマーが出す） |
| 天使 | 補給ドローン（♥の印） | 敵が出ないウェーブに現れる味方 |

**色の注意**：敵の体の主な色に、色の意味の5色（赤・緑・黄・青・紫）を使わない（共通の設計書 §5）。機械は灰・白・黒、目やランプは白く光らせるのを目安にする。

**弾の見た目**：プレイヤーの弾は白い光弾。スキル ◎（周りを回る玉）は小さな護衛ドローン、🔥 はプラズマの炎、❄ は冷却ガス。アイコンは共通の設計書 §9 のまま変えない。

### 8週間に収まるか
- 合計 22人日 で、使える 24人日 に収まる（8週目に約2日余る）。
- 7週目の終わりまでに描く新しい絵は 21人日 で、使える 21人日 に **ちょうど収まるが余裕はない**。
- プログラムで出す動き（揺れ、回転、点滅）が増えるぶん、Bさん（敵のプログラマー）の作業は約0.5人日増える（共通の設計書 §13）。

遅れたときの対策の候補（どれにするかはデザイナーとチームで決める）
1. 中枢機械の「呼ぶ」の動きを描かず、目が光るだけにする（雑魚は赤い `!` 円から出る）→ −1人日
2. 補給ドローンの浮く動きをプログラマーが出し、1枚の絵にする → −0.5人日

## 5. スキル系UI担当の素材と工数（約25人日）

| 素材 | 内容 | 人日 | 期限 |
|---|---|---|---|
| 絵柄合わせと仮アイコン | キャラの絵柄に合わせて、12種の仮アイコンを先に作る | 3 | 2週目 |
| 数字と記号のフォントの確認 | フリー素材のピクセルフォントに足りない記号（★ ⏱ × など）を描き足す | 0.5 | 2週目 |
| 操作案内の絵 | 矢印キー、マウス、手の動きのアニメ（キーに英字を描かない） | 2 | 最小版は2週目、完成は7週目 |
| カードの枠 | 通常／選んでいる／★の段階表示。金属のパネルと光る縁を目安にする | 2.5 | 3週目 |
| スキルアイコン 12種 | 32px。共通の設計書 §9 の記号をそのまま絵にする（⇉ ↖↗ ⇄ ⤳ ⟲ 🔥 ❄ ⚡ 💥 ⚔↑ ♥↑ ◎） | 7 | 6種は4週目、残りは6週目 |
| 画面のレイアウト | ホーム、カード選択、天使、クリア、死亡、一時停止の並べ方 | 1.5 | 4週目 |
| HUD | HPバー、経験値バー、ボスのHPバー（💀付き）、コイン、`23/50` の枠、スキル一覧の枠 | 3.5 | 5週目 |
| ボタンとピクトグラム | ▶ ⏸ ↻ 🏠 🔊 🏆 💀 ⚠ ⏱ ♥ ★ × など約12個、16px | 2 | 7週目 |
| 直しと統一 | 実際の画面で見て、色・大きさ・並びを直す（新しい絵は足さない） | 3 | 8週目 |
| **合計** | | **25** | |

- ファンタジー案より 1人日 多いのは、カードの枠と HUD の分。SF らしい細い線と光る縁は、小さいドット絵だとつぶれやすく、試し描きが増える。
- 8週間に収まるか：合計 25人日 は使える 24人日 を、7週目までの新しい絵 22人日 は使える 21人日 を、どちらも **約1日はみ出す**。

約1日を減らす対策の候補（どれにするかはデザイナーとチームで決める）
1. 仮アイコン12種をプログラマーが作る（プログラマーは工数に余裕がある）→ −1.5人日
2. 操作案内の絵は最小版のまま使い、完成版を作らない → −1人日

## 6. フリー素材（担当：Cさん、約2.5人日）

| 素材 | 探すもの |
|---|---|
| 床と壁 | 金属の床と壁のタイル（ドット絵） |
| 障害物 | コンテナ、柱、機械の箱 |
| エフェクト | 命中、爆発、プラズマの炎、冷却ガス、回復、レベルアップの光 |
| 弾 | 光弾、敵の弾（見つからなければプログラマーが図形で作る） |
| 音 | 効果音、BGM（10ウェーブごとに変えられるなら変える） |
| フォント | 数字と記号が入ったピクセルフォント |

- ファンタジー案より 1人日 多い。理由は2つ。
  1. 見下ろし視点の SF のドット絵素材は、CC0 のものが少なく、複数の素材を組み合わせて色を合わせる手間が出る。
  2. SF の素材には文字が入りやすい（画面の表示、警告の看板、機体の番号、「DANGER」などの表示）。確認と消す作業が増える。
- 候補：Kenney、OpenGameArt（CC0 で絞り込む）。中身とライセンスは取り込む前に確認する。
- ゲーム内にクレジット画面を作ると文字が出るので、CC0 を優先する。

## 7. デザイナー（補助）の作業

| 作業 | 内容 |
|---|---|
| 背景の飾り小物 | フィールドに置く飾り（配管、ケーブル、ランプ、床の傷など）。文字や番号を描かない。フリー素材で足りない分を補う |
| キービジュアル | 宣伝用の一枚絵（文字なし）。ゲームの外で使う |
| クリア画面の一枚絵 | 🏆 の後ろに出す絵。届くまでは 🏆 だけで出す |

どれも他の担当の作業を待たずに始められ、他の担当もこの作業を待たない。届いた時点で差し込む。

## 8. デザイナーに任せること

- 線の有無、色の数、陰影、頭身などの絵柄（共通の設計書 §11 の大きさの範囲内で）
- 各キャラと敵の細かいデザイン（§3 の役割と「ひと目で分かる理由」を守る範囲で）
- コマ数の増減（増やすときは工数を見直す）
- 描く順番（プログラムで使い始める順に合わせて入れ替えてよい）
- カードの枠と HUD の質感
- どの動きを絵で描き、どの動きをプログラムで出すかの線引き（Bさんと相談）
- §4 と §5 の対策をどれにするか

## 9. この案のよいところと気になるところ

**よいところ**
- キャラ担当の工数がファンタジー案より2日少なく、7週目の期限に収まる
- 光線銃なので、跳ね返りや貫通のスキルが見た目で分かりやすい
- 照明の変化で50ウェーブの進み具合を出しやすい

**気になるところ**
- UI担当が約1日はみ出す（§5）
- 機械の敵は形が似やすい。役割ごとに形（クモ型、一つ目、砲塔、コアの点滅）をはっきり変える必要がある
- 弓ではなく銃になるので、原作らしさは少し薄れる
- フリー素材を探して文字を消す手間が増える（§6）
