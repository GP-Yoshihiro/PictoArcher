## 1. 目的と理由

アーチャー伝説（Archero）型のローグライトアクションを、**文字を一切使わずに**作る。【決定】

前提は次の3つ。【決定】

1. 文字ゼロ（数字・記号・ピクトグラムは使ってよい）
2. 初見で分かる（説明なしで遊び始められる）
3. 動かして面白い（触った瞬間に気持ちいい）

**見た目はヴァンサバ（Vampire Survivors）のような2Dドット絵、仕組みはアーチャー伝説**を使う。【決定】
ヴァンサバから取り入れるのは見た目と雰囲気だけ。敵の数は原作のアーチャー伝説のように少なめにし、1体ずつの動きと予兆を見て避ける遊びにする。【決定】

世界観は **SF（ロボット系）**、主人公は **パワースーツを着た兵士**。【決定】見た目と敵の姿は世界観の文書に書く（§14）。

コンセプトは **「撃ちながら避け続ける。強くなるほど弾が目に見えて増える」**。【提案】
強化の結果が必ず画面上の見た目の変化として現れるようにすることで、文字の説明がなくても強化の意味が伝わる。

## 2. ゴール／やらないこと／失敗とみなすこと

**ゴール**
- 1つのステージ（50ウェーブ）を、説明なしで最初から最後まで遊び切れる【決定】
- 初見の人が下の「合格ライン」（§15）を満たす

**やらないこと（8週間の範囲外）**
- 2つ目のステージ【決定】
- スマホ対応、オンライン要素、課金や広告、装備、図鑑、デイリー要素
- 敵の大群（画面を埋める数十体〜百体の敵）【決定】
- 天使（ボスのあとに出る味方）【決定】
- プレイ中の武器の切り替え（武器は最初に1つ選ぶ。§4）【決定】
- プレイ途中の保存（1回のプレイは通しで遊ぶ）【提案】
- 🏹強化（ホームでの永続強化）と ⚙ 設定画面。手が空いたら足す候補にする（§13）【提案】

**失敗とみなすこと（動いていても失敗）**
- 画面のどこかに文字が1つでも出る（ロゴ、素材、エラー表示、ウィンドウタイトルの扱いは §5）
- 初見の人が「何をすればいいの？」と口にする
- 強化を選んでも何が変わったか分からない
- 50ウェーブの途中で「同じことの繰り返し」に感じて飽きる【提案】

## 4. 操作とコア体験

| 操作 | 内容 | 出所 |
|---|---|---|
| 移動 | WASD／矢印キー、またはマウス左ボタンを押したままドラッグ（押した位置が仮想スティックの中心） | 【提案】 |
| 射撃 | **常に自動射撃。移動中も撃てる**。一番近い敵を自動で狙う | 【決定】移動中も可／【提案】自動照準 |
| 武器を選ぶ | プレイを始める前に、3種から1つ選ぶ。プレイ中は変えない | 【決定】 |
| カード選択 | クリック、または 1 2 3 キー | 【提案】 |
| 一時停止 | Esc で ⏸ | 【提案】 |

- 移動中の連射速度は調整用の値として用意する（初期値は止まっているときと同じ 100%）。【提案】
- 敵がいないときは撃たない。【提案】
- 被弾したら短い無敵時間（点滅）。【提案】

### 武器（3種）【決定】種類・選び方／【提案】撃ち方

| 武器 | 撃ち方 | 得意なこと | 連射（目安） |
|---|---|---|---|
| 銃 | 光弾を1発ずつまっすぐ撃つ | どんな場面でも使いやすい | 速い（基準） |
| レーザー | 一瞬だけ直線の光線を出す。当たった敵をすべて貫く | 一列に並んだ敵 | 遅め |
| ランチャー | 小型の弾を撃ち、当たると爆発して周りの敵にも当たる（範囲攻撃） | 固まった敵 | 遅い |

- 武器を選ぶ画面は、ホームで ▶ を押したあとに出す。3つの武器の絵を並べ、選ぶとプレイが始まる。前回選んだ武器に印を付けておく。【提案】
- 初回はチュートリアル（§7）を銃で遊ぶ。武器を選ぶ画面は2回目のプレイから出す。【提案】
- 強化（§9）は3種すべての武器に効く。武器ごとの細かい見え方（例：レーザーの ⟲ は壁で光線が折れる）は A さんが決める（§16）。
- レーザーはもともと敵を貫くので、レーザーを選んだときは「ピアッシング」をカードの候補から外す。【提案】
- 数値（攻撃力、連射、射程、爆発の広さ）は ScriptableObject の調整値にする。

## 5. 文字ゼロのルール（全員必読）

前の版から変えない。【決定】

| 項目 | ルール |
|---|---|
| 禁止 | アルファベット・ひらがな・カタカナ・漢字すべて。`LV` `HP` `BOSS` `x2` `s`（秒）などの略語・単位も禁止 |
| 代わりの表記 | レベル `★5`／倍率 `×2`／時間 `⏱ 30`／割合 `+20%`／進行 `23/50` |
| 色の意味 | 赤＝危険・攻撃／緑＝回復／黄＝コイン・経験値／青＝防御・氷／紫＝レア。この5色は UI・拾うもの・エフェクトの意味だけに使い、敵の体の主な色やフィールドの照明には使わない（敵は灰・白・黒・茶・桃などから選ぶ。プレイヤーの弾は白）【提案】 |
| 予兆 | 敵の攻撃は必ず先に赤い線・赤い円で予告する |
| 操作の案内 | 手・矢印キー・マウスの絵のアニメで見せる。キーの絵に英字（W A S D、Esc など）を描かない |
| 絵文字 | フォントで出さない。すべてスプライト画像（ドット絵）で用意する |
| フォント | TextMeshPro のフォントアセットには **数字と記号だけ** を登録する。ドット絵に合うピクセルフォントを使う【提案】 |
| ボタン | ▶ 開始／⏸ 一時停止／↻ やり直し／🏠 ホーム／⚙ 設定／🔒 ロック中／🔊 音量 |
| 素材 | 取り込む前に文字が入っていないか確認する（UIパックの「PLAY」、看板、ロゴ、背景の張り紙や画面の表示など） |
| ウィンドウ・起動画面 | ウィンドウタイトルとアプリ名は OS が表示するもので画面内ではないため対象外。Unity のスプラッシュ画面は、出せない場合の扱いをチームで判断する【提案】 |

属性の色【提案】（毒は【仮】）
- 炎は赤、氷は青で、5色の意味と合う。
- 雷は黄色にすると「コイン・経験値」と見分けにくいので、**白い稲妻**にする。
- 毒の色はまだ決めない（§18）。紫にするとレアと重なるので、決めるときに注意する。

## 6. ゲーム進行フロー

```
[起動]
  ├ 初回 → タイトルを出さずにチュートリアル（ウェーブ0、銃）へ
  └ 2回目以降 → ホーム
[ホーム] ▶／これまでの最高記録 `37/50`（クリア済みなら ⏱ 最短タイム）
   ↓ ▶
[武器を選ぶ] 銃／レーザー／ランチャー
   ↓
[プレイ] 1つのフィールドで 50ウェーブ。障害物の並びはウェーブごとに変わる
   ↓
[クリア] 🏆 ＋ ⏱ クリアタイム ＋ 獲得コイン → ↻ ／ 🏠
[死亡]   💀 → 到達ウェーブ `23/50` と、選んだ武器と取得した強化のアイコン → ↻ ／ 🏠
```

- 仕様メモの「総ステージ数 50」は、この 50ウェーブのこと。【決定】
- フィールドは1画面に収まる広さで、カメラは動かない。【決定】
- 今のウェーブの敵を全部倒すと、同じフィールドに次のウェーブの敵が出てくる。【決定】
- ↻ やり直しは、同じ武器でもう一度始める。武器を変えたいときは 🏠 から。【提案】
- 死亡するとそのプレイは終わり、強化はリセット。【提案】
- 1回のプレイ（50ウェーブ）は 20〜30分を目安にする（1ウェーブ平均 30秒前後）。【提案】
- 保存するもの：最高到達ウェーブ、最短クリアタイム、コイン、前回選んだ武器。保存方法は JSON ファイル。【提案】

### 1ウェーブの流れ【提案】
1. 敵が出る位置に赤い `!` 円 → 敵が出現
2. 戦闘
3. 全滅 → 経験値とコインが自分に吸い寄せられる
4. 約1.5秒の休み。この間に障害物の並びを次のパターンに変え、画面上部の `23/50` が `24/50` に変わる → 1 に戻る

### 障害物のパターン【決定】数パターン・ウェーブごとに切り替え／【提案】中身
- 障害物の並びを **6パターン** 用意する（数は調整してよい）。どのウェーブでどのパターンを使うかは、ウェーブのデータ（ScriptableObject）に書く。
- 切り替えは休みの間に行う。今の障害物が消え、新しい障害物の位置に薄い影を約0.5秒出してから現れる。
- 新しい障害物がプレイヤーと重なる場合は、プレイヤーが離れるまでその障害物だけ出さない（閉じ込めない）。
- ボスと中ボスのウェーブは、障害物の少ないパターンを使う。
- 障害物の絵はフリー素材（コンテナ、柱、機械の箱）を使う。どのパターンも、プレイヤーが通れない袋小路を作らない。

### 50ウェーブの構成【決定】ボス2種・中ボス1種・天使なし／【提案】出る場所

| ウェーブ | 内容 |
|---|---|
| 5・15・25・35・45 | 中ボス（出る前に ⚠ が点滅） |
| 10・20・30・40 | ボスA（画面上部に 💀 付きのHPバー） |
| 50 | 最後のボス |
| それ以外 | 通常のウェーブ |

- 敵の種類は少しずつ増やす（§8 の「登場」）。26 で10種がそろい、31〜は組み合わせと強化版で変化を付ける。
- 中ボスとボスは同じものが繰り返し出るので、出るたびに HP と速さを上げ、ボスは攻撃パターンも足す（§8）。
- 強化版の敵は、見た目を少し大きくし、色を濃くする（§5 の5色にはしない）。
- 10ウェーブごとに、フィールドの色合い（照明）を少し変えて、進んでいる感じを出す。背景の素材はそのまま使う。色合いは彩度を抑え、§5 の5色に見えないようにする。

### レベルアップ【決定】自己強化系／【提案】流れ
経験値バーが満タン → 時間停止 → カード3枚 → 1枚選ぶと再開。ウェーブの途中でも発生する。
50ウェーブで 20回前後のレベルアップを目安にする（調整値）。全部の強化が上限に達したら、カードは ♥回復 と コイン に置き換える。

### 一時停止メニュー【提案】
▶ 再開／↻ やり直し／🏠 ホーム／🔊 音量

## 7. チュートリアル（ウェーブ0）【提案】

武器は銃で遊ぶ。

1. 敵1体だけ。矢印キーとマウスの絵がアニメで動きを見せる → プレイヤーが動く
2. 近づくと自動で弾が飛ぶ → 撃つのは自動だと分かる
3. 1体目を倒すと必ずレベルアップ → カード選択を一度体験させる
4. 2体目は弾を撃つ敵。赤い予兆線を見せて、避けることを覚えさせる
5. 倒すと `1/50` が出て、そのままウェーブ1が始まる

案内の絵はプレイヤーが一度その操作をしたら消える。2回目以降の起動では出さない。

## 8. 敵とボス

敵は「役割」で決め、見た目と名前は世界観の文書で決める（§14）。【提案】

### 通常の敵（7つの見た目で10種）【決定】種類／【提案】予兆・登場

見た目（モデル）は7つ。モデル1〜3は、同じ見た目で攻撃の違う2種がある。【決定】

| モデル | 種類 | 動き | 予兆 | 登場 |
|---|---|---|---|---|
| 1 | 単発攻撃型 | 止まって狙い、1発まっすぐ撃つ | 赤い線 | 1〜 |
| 1 | 単発範囲型 | 1発撃ち、着いた所で爆発する | 着く場所に赤い円 | 11〜 |
| 2 | 三発扇型 | 扇形に3発を同時に撃つ | 赤い線3本 | 6〜 |
| 2 | 五発連射型 | 同じ向きに5発を続けて撃つ | 太い赤い線 | 16〜 |
| 3 | 接触攻撃型 | プレイヤーを追ってくる、体当たり | なし（遅い） | 1〜 |
| 3 | 自爆型 | 突進して自爆する | 赤い円が広がる | 6〜 |
| 4 | 地面燃焼型 | 床に炎を残す。炎の上にいるとダメージ | 燃える場所に薄い赤い円 | 16〜 |
| 5 | 落雷型 | プレイヤーのいる場所に雷を落とす | 赤い円が縮んでから落ちる | 21〜 |
| 6 | ハンマー回転型 | ハンマーを振り回しながら近づく | 回る範囲に赤い円 | 11〜 |
| 7 | 時間制限型 | 出てから一定の時間がたつと、プレイヤーを即死させる攻撃を出す【仮】（§18） | 頭の上に ⏱ と残り秒数。最後の3秒は画面の縁が赤く点滅 | 26〜 |

- 同じモデルの2種は、見た目のちょっとした違い（武器の部分など）で見分けられるようにする。描く量を減らす場合は、大きさと予兆の違いだけで見分ける（世界観の文書 §4 の対策）。
- 時間制限型は初見で理不尽に感じやすい。出すのは 26〜 にし、残り秒数を必ず見せる。即死の代わりに大きなダメージにするかは、プレイテストで決める（調整値）。【提案】
- 地面燃焼型の炎は、一定時間で消える。

### 中ボス（1種）【決定】1種／【提案】中身
- HPが減ると分裂する。5・15・25・35・45 に出る。
- 出るたびに HP と速さを上げ、分裂の数を増やす。

### ボス（2種）【決定】2種／【提案】中身
| ボス | 出るウェーブ | 攻撃 |
|---|---|---|
| ボスA | 10・20・30・40 | 10：突進（赤い線）／雑魚を呼ぶ（赤い `!` 円）。20 から範囲攻撃（赤い円）を足す。30・40 は HP と速さを上げ、攻撃の間隔を短くする |
| 最後のボス | 50 | 3パターン：突進／弾幕（光ってから）／雑魚を呼ぶ。HPが半分を切ると色と光り方が変わり、間隔が短くなる |

- ボスAの範囲攻撃は、新しいコマを描かず「ため」の動きを使い回す。
- 最後のボスの見た目の変化は、プログラマーが色と光り方で出す（変化のコマは描かない）。
- 強化版の色は §11 のとおりプログラマーが出す。

数値（HP・攻撃力・速度・出現数・時間制限の秒数）はすべて ScriptableObject の調整値として扱い、プレイテストで決める。

## 9. 強化（15種、カード26枚）【決定】種類／【提案】アイコン・見え方・重ね取り

レベルアップで選ぶのは、自分を強くする強化だけ。【決定】
15種のうち、6・7・8・11 は中にいくつかの種類があり、それぞれが別のカードになる。カードは全部で26枚。
カードには **大きいアイコン＋数字＋約1秒の実演アニメ** を入れる。

| # | 強化 | カード | アイコンの絵 | 画面での見え方 | 重ね取り |
|---|---|---|---|---|---|
| 1 | HP回復 | 1 | ♥＋ | 緑に光り、HPバーが戻る | 何度でも（HPが満タンのときは候補から外す） |
| 2 | 最大HPアップ＋回復 | 1 | ♥↑ | HPバーが伸びる | 最大5 |
| 3 | 攻撃力 +% | 1 | ⚔↑ | 弾が大きく光る | 最大5 |
| 4 | 移動速度 +% | 1 | 足＋↑ | 走りが速くなり、残像が出る | 最大3 |
| 5 | 攻撃速度 +% | 1 | 弾＋» | 撃つ間隔が短くなる | 最大5 |

## 11. ドット絵の方針【提案】

細かい見た目（線の有無、色の数、陰影の付け方、キャラの頭身）はデザイナーが決める。ただし、工数は下の大きさを前提に見積もっているので、大きさを変えるときは工数も見直す。

| 項目 | 前提 |
|---|---|
| 描画の基準解像度 | **270×480**（1080×1920 の 4倍拡大）。URP 2D の Pixel Perfect Camera を使う |
| フィールド | 1画面＝270×480 の中に収める（壁を含む）。HUD はフィールドの上に重ねる。戦える広さは壁の内側で HUD の下、およそ 240×400 |
| タイル | 16px のマス目を基準にする（フリー素材もこの大きさのものを選ぶ） |
| プレイヤー・通常の敵 | 24〜32px 四方 |
| 中ボス | 48〜64px 四方 |
| ボス | 64〜80px 四方（横幅が 270 になったので、前の版の 96 から小さくする） |
| 強化のアイコン | 32px 四方（カードでは 2倍で表示） |
| 武器のアイコン | 32px 四方（武器を選ぶ画面では 2倍で表示） |
| HUD のピクトグラム | 16px 四方 |
| 向き | 左右だけ（右向きを描き、左は反転）。上下の向きは描かない |
| 被弾の白い光り | プログラマーがシェーダーで出す（コマを描かない） |
| 強化版の色 | プログラマーが色を変えて出す（別の絵を描かない） |

- 背景とエフェクトはフリー素材なので、キャラの絵柄と合うかを最初の1週目に確かめる。合わない場合は、素材側の色をプログラマーが合わせる。大きさが合わず使えない場合は、別の素材を探す（描き直しはしない）。
- フリー素材は CC0 を優先する。CC-BY は、クレジットをゲームの外（README と配布ページ）に書けば使ってよい。素材を買う予算は無いものとする。
- 絵の受け渡し：絵の担当は PNG のスプライトシート（コマを横一列、1コマの大きさをそろえる）で渡す。Unity への取り込みとアニメの設定は、そのキャラや敵を担当するプログラマーが行う。
- 絵が届くまでは、プログラマーは仮の図形で作り、届いたら差し替える。
- 全員の素材について、間に合わない場合の代わり（仮の図形、既存の絵の流用）を先に決めておく。

## 12. 技術方針【提案】

| 項目 | 方針 |
|---|---|
| テンプレート | Unity 6 の 2D（URP 2D Renderer）テンプレートで作成済み |
| ドット絵 | Pixel Perfect Camera（基準 270×480）。画像は Filter Mode を Point、圧縮なしで取り込む |
| 画面 | Player Settings で縦長のウィンドウ（540×960）にする。全画面では整数倍で拡大し、左右は黒い帯 |
| 入力 | Input System。キーボードとマウスのドラッグを同じ「移動ベクトル」に変換する |
| データ | 武器・強化・敵・ウェーブ・障害物のパターンは ScriptableObject。新しい強化や敵、ウェーブはデータを足すだけで増やせるようにする |
| 文字 | TextMeshPro、数字と記号だけのピクセルフォントのアセット |
| シーン | Boot／Home／Run の3つ。武器を選ぶ画面は Home の中に置く。Run シーンはフィールド1つで、ウェーブはデータを順に読んで敵と障害物を出す |
| 共同作業 | シーンを同時に編集しない。担当ごとにプレハブを分け、シーン編集は1人に決める。UnityYAMLMerge を各自設定する |
| Claude のルール | リポジトリの一番上の `CLAUDE.md` に、文字ゼロのルール（§5）、フォルダ構成、テストの書き方、「シーンは担当の1人だけが編集する」を書く。この版で変わった基準解像度（270×480）は、計画2の最初に直す |
| ブランチ | 担当ごとにブランチを分ける。`main` へは直接入れず、ほかの1人が確認してからマージする。Claude が書いたコードも、マージ前に人が読む |
| ビルド | Windows と Mac のスタンドアロン |
| テスト | 純粋なロジック（ダメージ計算、強化の重ね取り、カードの抽選、ウェーブの進行、障害物のパターンの選び方）は EditMode テストを書く |

プログラマーの余裕が残ったときに、上から足す。絵が要るものは、絵の担当に余裕があるときだけ。

3. 🏹強化（ホームでの永続強化。UI担当のアイコンが要る）

## 15. 合格ライン（毎週のプレイテスト）【提案】

説明を一切せずに初見の人に渡して、

1. 30秒以内に自分から動いて敵を倒せるか
2. ウェーブ10のボスまで誰の助けもなく進めるか（ボスAが入る4週目から測る。3週目は「ウェーブ5まで」で測る）
3. 強化のカードを選んだあと、その効果を自分で言えるか
4. 武器を選ぶ画面で、3つの武器の違いを絵だけで想像できるか（4週目から測る）

テスト中は観察する人も口を出さない。止まった場所と、その人が口にした言葉を記録する。
毎週まだ遊んだことのない人を探す。見つからない週は2回目の人で測り、記録に「2回目」と書く。観察と記録は、その週に手の空いている人が行う。
